### [x] T2. Deadline-хелперы
Файл: `App/src/tasks/task_scan_controller.c`.
Содержание: `Scan_MsToTicks`, `Scan_DeadlineReached`, `Scan_DeadlineRemaining`; unit-тесты на границы и переполнение тиков.
Приёмка: тесты на 0, остаток, истёкший deadline.

### [x] T3. Бюджет подготовки
Файлы: `task_scan_controller.c`.
Содержание: `SCAN_SSI_PREP_BUDGET_MS 6000`; `Scan_PrepareRead(deadline)`; STOP и FLUSH в одном бюджете; каждое ожидание `min(2000, remaining)`; без ретрая по таймауту; RESEND max 2 и только при `remaining >= 2000`; исчерпание — E602.
Приёмка: STOP/FLUSH не могут суммарно превысить 6 с; при остатке < 2000 RESEND не отправляется.

### [x] T4. Фаза чтения
Файл: `task_scan_controller.c`.
Содержание: `read_phase` начинается по START ACK; `read_deadline = min(now + read_timeout, txn_deadline)`; `read_timeout = timeout_sec>0 ? *1000 : 4000`; пакеты, ACK, REVISION и RESEND срок не сбрасывают; `CHECKSUM_ONLY` сохраняется; по истечении — E603.
Приёмка: валидные данные завершают чтение сразу; ACK не завершает; поздний пакет не продлевает срок.

### [x] T5. D1: драйвер
Файлы: `App/src/scan_uart_driver.c`, `App/inc/scan_uart_driver.h`.
Содержание: deadline-параметр и `min(remaining)` во всех ожиданиях; обновить вызовы в `task_scan_controller.c`.
Приёмка: отправка возвращает `false` не позже deadline; существующие вызовы без deadline не ломаются (обёртки/дефолт).
